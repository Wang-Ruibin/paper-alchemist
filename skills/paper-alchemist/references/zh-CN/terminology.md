# 有证据约束的领域术语

## 准备术语提示

使用已审阅术语库和确认后的研究材料：

```bash
paper-alchemist term-brief --registry <registry.json> --context <paper-context.yaml>
```

阅读来源、问题变体定义、易混概念和所需上下文。训练期的临时术语库不等同于
覆盖全语料的正式资源。

## 附加到章节写作提示

```bash
paper-alchemist brief <module> --profile <name> --language en --format latex --context <paper-context.yaml> --terminology-registry <registry.json>
```

仍须满足画像的语义完整性门槛。术语提示不能绕过未完成观察、过时画像、
缺失整合或缺少研究事实。

## 消除歧义

完整问题名称优先于缩写。`resolved` 表示存在特定匹配条目，并不表示整个
研究模型已确认。`needs-expansion`、`ambiguous` 和 `unclassified` 需要核对
完整名称或变体。术语库未收录、但已提供完整名称、实体、决策、目标与约束的模型
标为 `context-defined`，按照已确认研究材料继续，不声称术语库提供了经过核验的
定义。术语库覆盖不足不等于研究事实缺失；未知缩写和不完整模型仍需澄清。
将真正缺失的事实翻译成简洁问题或清单，不把内部字段当作用户任务。
对于结构化问题材料，结合 `full_name`、`name` 和 `title` 一起核对。
明确提供的全称可以消除共用缩写的歧义；完整名称相互冲突时仍须澄清，
不能默默选取其中一个字段。

核对目标方向、聚合方式、约束、指标定义和证明状态。同一缩写在本语料中
可能表示不同模型。
完整变体名称包含基础问题名称时，若基础名称每次出现都嵌在该变体名称中，
选择更具体的变体。分别提及两个模型时仍需核对变体；完全相同的完整别名仍有歧义。

## 保持证据边界

用术语定义核对当前已确认模型，不用语料默认定义替换用户明确指定的变体。
不得从参考论文借用算法细节、复杂度证明、数值结果、创新性或参考结果声明。
缺少中文语料时，中文仍属于语言辅助，而非已观察的文风。
