# Paper Alchemist

### 从研究规划到有据写作，再把审稿意见落实为核实过的修改。

空白版提供研究规划、文献证据整理、审稿及论文写作流程，不包含内置论文资料库。使用语料指导写作前，先蒸馏自己的参考论文或导入已有指导。

## 它能帮你做什么

- 根据已有材料梳理研究问题和提纲、比较方法选择并识别证据缺口；按实际读过的来源能支持什么，组织文献。
- 分别处理摘要、引言、相关工作、问题定义、方法、实验设置、结果分析和结论；可以只写一节，也可以组装全文并统一符号、术语、数据和引用。
- 从 PDF、LaTeX、DOCX、Markdown 或文本论文中分节蒸馏写作指导，保留来源依据与术语的适用范围。
- 显示哪些论文已完成蒸馏，扫描新增、修改或改名的论文，并在保留现有指导的基础上增量更新。
- 导入、导出已完成的指导，让另一个项目或另一台电脑无需原始论文即可复用。
- 按研究事实检查稿件。正文只保留学术内容，操作记录和审阅说明另存。
- 从相关科学与编辑角度审阅现有稿件，把每项审稿意见对应到修改、有证据的回复或未解决事项；续接时核对当前文件，材料变化后复核受影响的判断。

英文写作与中文辅助分别处理。指导只能帮助组织和表达研究，不能替你提供实验结果或参考文献。

## 从安装到第一篇论文

你需要：

- 能使用本地插件和终端的 Codex，以及一个存放研究材料的项目文件夹。
- 首次安装时联网。Codex 会准备独立 Python 环境，无需手动安装 Python、pip 或修改 PATH。

下面标为“发送给 Codex”的文字请复制到 **Codex 的聊天输入框**，不用粘贴到 PowerShell，也不用自己编辑配置文件。

### 1. 请 Codex 安装

发送给 Codex：

```text
请从 https://github.com/Wang-Ruibin/paper-alchemist
安装 Paper Alchemist。先阅读仓库 README 和 docs/INSTALL.md，
按说明准备独立运行环境，并通过 Codex 原生插件市场命令完成安装。
复用兼容的 Python；没有时自动准备私有运行时，不修改系统 PATH。
保留我已有的配置和写作资料，核验实际安装的插件及其运行环境。
完成后告诉我是否需要新建对话，以及接下来可以做什么。
```

安装完成后，新建 Codex 对话并使用 `$paper-alchemist`。如果安装受网络、GitHub 权限或客户端版本影响，把完整报错交给 Codex 继续处理；你不需要手工串联安装命令。下载只发生在明确的安装或升级步骤。

### 2. 准备写作指导

发送给 Codex：

```text
使用 $paper-alchemist 帮我建立写作指导。先询问参考论文的位置，检查清单，
再按章节完成蒸馏、综合与整合。告诉我已完成和待处理的论文，
只有必要步骤完成后才确认可用于写作。如果我已有导出的指导包，请帮助导入。
```

完成标志：Codex 确认你的指导已可用于写作，并说明实际来源与适用范围。抽取文本不等于完成蒸馏，本版不会自动引入私人语料。研究规划、文献整理和评阅现有稿件可以先开始。

### 3. 写一节或完成全文

在你的研究项目里打开 Codex，提供已核实的方法说明、模型、结果表和参考文献，然后发送：

```text
使用 $paper-alchemist，根据这个项目中已核实的研究材料写一篇英文论文。
先检查材料，列出真正影响写作的缺失事实并向我确认。
按章节分别使用写作指导，摘要最后写，最终统一术语、符号、数值和引用。
将论文保存为 paper.md 和 main.tex，审阅记录单独保存。
正文只保留论文内容，不加入助手开场白、AI 提示或工作流程说明。
```

只需要一节时，可以说：“根据这些方法说明写 methodology，先核实输入、状态变化和输出。”已有稿件也可以直接请求修改。研究规划、文献工作和评阅现有稿件不要求先准备好写作指导。

完成标志：得到请求的章节或全文，关键事实能对应你提供的材料。导出 PDF 还需要 LaTeX 编译器；需要时请 Codex 单独准备并检查版面。

## 规划、查文献、审稿或修订

从当前需要的阶段开始，可以只做一项，也可以衔接完整流程：

```text
使用 $paper-alchemist，根据我的笔记形成研究计划。分清已有发现和拟议方案，
指出证据缺口并提出合适的提纲。文献先从我已有的参考资料开始，核实可取得的来源，
说明每篇能支持哪些论断，只就影响结果的决定或事实向我补问。
```

已有稿件和审稿意见时，可以发送：

```text
使用 $paper-alchemist，结合研究材料审阅 paper.md，并处理 reviewer-comments.txt。
逐项保留审稿意见，进行有依据的修改，核实实际改动后再写回复。
将修订稿保存为 paper-revised.md，回复保存为 response.md，
证据和修订记录放在 review/，未解决的科学问题继续保留在审阅记录中。
```

完成标志：交付请求的计划、综合、审阅或修订，证据有出处，剩余问题明确。只有文献条目不等于核实了被引论断。审阅反馈属于 Agent 辅助，不等于独立同行评审，也不预测期刊接收。需要系统综述时，请明确要求制定并执行检索与筛选方案。

长项目可以让 Codex 从保存的研究和审阅记录继续；它会先核对当前版本，再复用旧判断。工作流与本地证据检查器详见[研究流程参考](skills/paper-alchemist/references/zh-CN/research-workflow.md)。

## 增加论文或检查变化

发送给 Codex：

```text
使用 $paper-alchemist 显示已蒸馏论文，并扫描参考论文文件夹是否有变化。
先告诉我新增、修改、改名或删除的论文。对我确认的变更进行增量蒸馏，保留已有指导。
如果新文件夹里只有新增论文，请把它作为附加来源，不要替换原有资料库。
```

扫描本身不会重新蒸馏。新增来源完成审阅、综合和整合后才参与写作；原论文修改后，与旧内容不再匹配的指导需要重新审阅。

## 在别的项目或电脑使用

同一台电脑安装一次即可在其他研究项目里调用。需要携带你自己新增的指导时，直接告诉 Codex：“导出当前完整写作指导，包含新增论文，供另一台电脑导入使用。”

导出的指导包含已审阅的写作规则、术语和来源记录，不包含参考论文原文、当前研究材料或稿件。增量更新原论文时，仍需重新连接对应的原文件夹。

## 环境、隐私与适用边界

- 独立运行时在首次安装时准备，普通写作命令不会下载环境。Windows 与 WSL 分别准备各自环境；无需激活虚拟环境。
- Python 解释器按当前系统下载，未把某台开发电脑的虚拟环境塞进插件。离线电脑需要提前准备同系统、同架构的运行环境；联网安装不等于离线安装包。
- 论文与研究材料保留在你的项目里。本地脚本不调用额外的大模型 API；Codex 阅读的内容仍由你正在使用的 Codex 服务处理。
- 文献发现使用宿主已有的检索工具及公开查询。无法取得来源时，未读文献保持待确认。本版支持 Codex 原生安装；工作流指导和本地文件约定可以复用，其他宿主尚未验证。
- 不编造方法、数据、贡献、显著性或文献。复制风险检查和自动审阅有范围限制，投稿前仍需核实研究内容与目标期刊要求。

## 遇到问题

把安装、扫描或写作时的完整报错发给 Codex，并说明你使用 Windows、WSL、Linux 还是 macOS。环境未就绪时，让它按[安装说明](docs/zh-CN/INSTALL.md)继续准备；找不到参考论文时，先确认是复用已有指导还是要更新原论文。

需要更新插件时，说：“更新 Paper Alchemist，保留我已有的写作指导和研究文件，并核验更新后的安装。”
