# 初稿证据审计

[English](../draft-audit.md)

## 检查当前初稿

起草或修改章节、组装全文后，将实际交付文本与已确认研究事实逐项核对。
语料提供写作惯例，不提供当前研究结果。

```bash
paper-alchemist audit-draft draft.md --context paper-context.yaml --module section --out draft.audit.json
```

单章节使用实际模块名。可加 `--terminology-registry registry.json` 和
`--corpus-prose permitted-sections/`。后者读取允许使用的 `.txt` 章节，排除
`full.txt`，报告连续至少 13 个规范化英文词的重合。不指定这个覆盖参数时，命令
使用选定画像或内置语料中绑定来源的文字指纹；可用 `--profile` 和 `--workspace`
选择其他资料。指纹只包含哈希及来源绑定，不包含参考句子。启用的已审阅新增指导
有对应指纹时也会参与检查。报告分别说明实际参照数量和应有数量。不得用最终
留出文本调优开发初稿。既无指定原文又无指纹记录时，复制检查未执行。

这是针对索引所含已识别抽取章节及另行审阅的 PDF 解码变体的精确文字重合筛查，
不证明语义原创性，不覆盖中文正文、未恢复版式或 PDF 的每个区域。将范围及仍然
有效的编码不确定性保留在独立评审记录中；重合列表为空不等于完整的抄袭风险排除。
报告还会标出参照文本中的控制码或替换字形不确定性；词语匹配可能漏掉经过损坏
词语的重合。接受复制检查前，须结合原文或已核实的恢复文本解决这些窗口。
重合列表为空不能消除编码警告。该信号采取保守判断，可能涉及数学内容；不会
推测缺失字母，也不会在警告中输出参照正文。

命令检查引用键、数值、必需事实、含糊变体、已确认的禁用表达和可疑主张。
还会拦截可识别的助手开场白、AI 身份自述和稿件中的评测提示。这只是有限的词法
检查；仍须通读全文，清除隐含的写作建议、流程解释和任务说明。作为研究内容的
AI 方法介绍以及影响论证的研究局限，仍属于正常论文内容。
否定陈述也须核对依据。顶层 `materials` 描述写作者收到了或核对了哪些材料，不能
证明研究未进行某项实验、检验或审核。仅以这些写作字段为依据的科研主张不能通过
台账校验。保留已确认的科学局限，涉及方法输入／输出状态的歧义须根据研究事实解决。
已渲染的作者年份或数字引用须与文献键对应。数字在事实中出现，不等于其样本群体、
指标、比较对象、方向和单位正确。应结合原始事实解释发现，不要仅为词法诊断改写
本来正确的内容。
核查相对百分比是否被写成百分点差，以及逐实例相对提升的均值是否被写成原始均值
占优。引用必须支持所附分句，包括归于该文献的任何实现细节。

数值诊断接受等价的小数补零、千位分隔符和科学计数法，不会通过舍入丢失精度。
百分数单位仍单独区分；`percent` 和 `per cent` 的文字写法与 `%` 表示同一单位，
百分点并非相对百分比的别名。已审阅数值显示可使用以 `_percent` 结尾的标量字段，
或该字段下的 `value`、`exact`、`display` 和 `decimal_N` 明确声明百分数单位。
度量对象也可通过 `unit: "%"` 或 `unit: percent` 为这些度量字段声明相同单位。
同一对象中的 `n` 等样本计数不会继承百分数单位。未标明单位的比值不会自动换算
成百分数，事实中未给出的舍入值仍须提供依据。

简单 Markdown 或 LaTeX 表格中，完整的单个数值单元格可继承本列显式表头中的
`%` 或 `(percent)` 单位。该单位不延伸至相邻列、表外正文或后续表格。同一上下文
中的计数不能为同数值的百分数提供依据。嵌套／跨列表头以及混合数字注释不会
自动继承单位；应明确标注单位并审核其含义。这些格式规则不会将未标明单位的
比值换算成百分数，也不构成完整语义评审。

数学标记中的十的幂数值写法（例如 `\(10^{-9}\)` 和
`\(1.23\times10^{-3}\)`）按科学计数法比较。指数不会成为独立的研究数值；
系数、符号和完整精度均保留，这条格式规则不计算一般符号表达式。
稿件若根据已给数据计算代数结果，应先核对运算数、单位、汇总口径和适用范围，
再将其记录为计算事实。计算过程和原事实绑定保存在正文之外，后续评审绑定到
更新后的上下文。不得仅因数值出现在稿件中就将其加入事实，也不得把计算差值
当成新增实验。

LaTeX 的 `thebibliography` 内显式带键的 `\bibitem{key}` 条目，以及 Markdown
References/Bibliography（参考文献）标题下的 `[key]` 文献段落，按该键对应的
已授权文献元数据核对数字。某条文献的年份、卷号或页码不能为另一条文献或正文
实验结果提供依据。未对应的文献仍须有显式映射。这些检查不证明引用所附主张
得到支持，也不替代完整语义评审。

Markdown 文献标签也可使用列表符号或 `- **key.**` 这样的加粗键。Unicode
减号保留负值。在普通文本和文献条目中，数字之间的 TeX 双短横线表示范围；
数学表达式中的相同字符仍保留其算术含义。已识别的表格宽度、间距及孤行控制参数属于
排版，表格数值单元格和正文中的相同数值仍须核对事实。上述格式规则都不代表
完成了语义评审。

## 恢复参照文本编码

参照 PDF 出现不确定字形时，由 Agent 准备私有候选文本：

```bash
paper-alchemist prepare-copy-evidence paper.pdf --workspace .
```

结合原始页面核对受影响词语及其实际字体。需要显式的来源／字体／编码字形映射时，
通过 `--font-reviews reviewed-fonts.json` 传入已标明审核者的记录。每条映射绑定
PDF 哈希、字体对象及渲染图像证据。不得全局替换控制码，也不得根据上下文猜字母。
候选文本和回执保持私有；准备候选本身不执行语义评审，也不接受稿件。

核对完整解码文本并解决所有已报告字形警告后，为清单中的准确来源登记回执：

```bash
paper-alchemist register-copy-evidence --profile library --source paper.pdf --receipt candidate-receipt.json --reviewer "identified reviewer" --review-scope "All PDF pages decoded and source-bound glyph recovery checked; this review covers English lexical evidence only." --workspace .
```

路径及实际审阅范围由 Agent 填写。批量登记可用 `--batch source-receipts.json`
替代单个来源／回执组合；后续出错时，之前的有效登记仍保留。登记会核验原始
PDF 字节、页数、候选文本的准确字节及当前章节绑定，只增加哈希，不改写原始
提取文本、观察记录或整合指导。原始指纹和警告仍然保留。匹配的已审阅解码变体
可以解决该来源在有限词法筛查中的有效编码信号；来源或章节哈希改变后，不能复用。

可移植导出携带已审阅哈希，不携带解码正文。更新后的内置资产可为现有资料库提供
匹配的查重证据，无需改写其快照。中文及语义原创性审核仍须有各自的证据。

## 完成语义评审

逐句审核事实及引用，记录准确文本片段、适用的上下文路径、支持或不支持的判断
与理由。核查公式、假设、条件性定义及推理，包括聚合方式或分母变化。
发现无依据内容时修订，或向用户获取缺失事实。

评审 JSON 包含 `draft_sha256`、`context_sha256`、`reviewer_kind`（`agent` 或
`human`）、`reviewer`，以及设为 `all-factual-and-citation-bearing-sentences` 的
`coverage`。哈希取自诊断报告。`checks` 须显式评价 `factual_entailment`、
`terminology_and_notation`、`citation_entailment`、`claim_calibration`、
`cross_section_consistency`、`copying`、`format`。只有实际完成相应审核后才写
`pass`，否则初稿保持未完成。

每条 `claims` 包含 `text`、`context_paths`、`judgment: supported` 和实质性
`rationale`。路径可定位嵌套字段或列表索引，如 `research.results.0`。
其他正文通过具有理由的 `non_claim_spans` 逐项说明，不能只审核一句而漏掉其余内容。
派生计数须在 `derived_values` 中提供准确 `claim_text`、`value`、
`operation: sum` 及至少两个绑定事实的 `operands`；每个操作数含 `context_path`
和显式数字 `literal`。算术正确不代表不同样本群体能够合法相加。

```bash
paper-alchemist audit-draft draft.md --context paper-context.yaml --module section --semantic-review draft.review.json --out draft.audit.json
```

正文或上下文变化会使旧评审失效。重新检查受影响主张并生成绑定新哈希的记录。
只有机械检查和记录的语义检查均通过时，退出码才为零；未完成评审的诊断仍属于
未完成结果。评审文件只保存到用户或评测任务授权的路径。

## 评价写作质量

证据检查不能衡量语言是否精练、组织是否合理、是否符合语料风格。还须检查对应
模块的论述功能、专业措辞、术语与符号一致性、解释强度、重复和衔接。
交付稿应当采用投稿论文形式，评审记录及操作说明放在稿件之外。全文另做
跨章节通读，尤其将摘要与正文核对。Agent 评审不等于人工专家审核，也不能保证
期刊接受。在开发工作区中，系统比较遵循冻结的 `evaluation/PROTOCOL.md`；
打包运行时不依赖仓库评测数据。

事实审核后，另按出版顺序对组装全文做一遍编辑通读。直接陈述方法和报告规则：
将“所提供的舍入值”等写作输入措辞改为实际显示约定，删除假设性的誊写或审计
纠错说明。保留影响结果解释的已确认科学限定，将其他重复局限集中表达。
摘要和主文分别在缩写首次使用时展开。表格跟随使用其结果的论述，重新核对
编号及上下文指引；浮动图表调整后，显示公式仍应紧跟引入文字。实质修订同步
到两种格式及受影响章节，保留事实、引用和符号绑定。重新编译并查看每个变化
后的页面。编辑检查记录放在论文之外，旧稿评审不能接受修订后的正文。
